> S8.1 spike harness live in Chrome against `https://cogis.ai/spike/s8-1.html`.

## Harness architecture (one-paragraph reminder)

The spike page (`web/spike/s8-1.html`) is a static HTML observation harness
with buttons that drive the drop-case matrix. The spike extension
(`spike-ext/`) is an MV3 extension whose content script (`web-bridge.js`)
implements the addendum §3.9 postMessage contract, and whose background SW
(`service-worker.js`) returns canned `WEB_BRIDGE_RESULT_CHUNK` /
`WEB_BRIDGE_PLATFORM_DONE` replies for accepted searches. Both are throwaway
and get deleted after S8.1 closes.

## Chronological observations

### Round 1 — cold load, first handshake attempt (found 2 harness bugs)

**Actions:**

1. Loaded `spike-ext/` unpacked in Chrome. Extension card showed no errors.
   SW console logged `[s8.1-sw] sw_loaded {manifestVersion:"0.0.1"}`.
2. Opened new tab, opened DevTools (F12), enabled "Preserve log".
3. Navigated to `https://cogis.ai/spike/s8-1.html`.
4. Observed cold-load console output.
5. Clicked "Send HELLO now (manual)".

**Observed on cold load (before any button click):**

```text
[s8.1-page]  page_loaded  origin:"https://cogis.ai", readyState:"loading", sessionNonce:"0e3ea98e53814b8f7697c8da734cd82b"
[s8.1-bridge] bridge_loaded  href:"https://cogis.ai/spike/s8-1.html", readyState:"interactive", runAt:"document_idle"
              counters: {originDropCount:0, nonceDropCount:0, malformedDropCount:0, acceptedCount:0, helloCount:0}
```

**Findings from cold load alone (no clicks):**

- `event.origin` for a page loaded at `https://cogis.ai/spike/s8-1.html` is
  the exact string `"https://cogis.ai"` — no path, no trailing slash. String
  equality against `EXPECTED_ORIGIN = 'https://cogis.ai'` will match.
- Bridge content-script is live at `document_idle` with
  `document.readyState === "interactive"` — that is, before `load` fires.
- Session nonce generated by the page: 32-char lowercase hex (128 bits),
  from `crypto.getRandomValues`, scoped to a single page load.
- Counters initialize at zero on load; no persistence across reloads (see
  Bug 2 below for why that ended up being the right design).
- Extension SW is present and active at cold-load time (`sw_loaded` line).

**Observed on "Send HELLO now (manual)" click:**

Handshake half-worked. Then two bugs surfaced:

```text
[s8.1-page]   page_send_hello  label:"manual", nonce:"0e3ea98e..."
[s8.1-page]   page_recv        origin:"https://cogis.ai", data:{type:"COGIS_HELLO", nonce:"0e3ea98e...", v:1}
[s8.1-bridge] accepted_hello   nonce:"0e3ea98e...", counters:{helloCount:1, acceptedCount:1, ...}
[s8.1-bridge] persist_error    "Cannot read properties of undefined (reading 'session')"
[s8.1-page]   page_recv        origin:"https://cogis.ai", data:{type:"COGIS_READY", nonce:"0e3ea98e...", v:1, extVersion:"0.0.1", capabilities:{search:true, cancel:true}}
[s8.1-bridge] drop_malformed   reason:"unknown_type", type:"COGIS_READY", counters:{malformedDropCount:1, ...}
[s8.1-bridge] persist_error    "Cannot read properties of undefined (reading 'session')"
```

#### Bug 1 (fixed in PR #28) — bridge dropped its own outbound reply

`window.postMessage(msg, targetOrigin)` dispatches to **every** listener on
the target window, **including the sender's own listener**. When the bridge
posted `COGIS_READY` back to the page, its own `window.addEventListener('message', ...)`
ran again, saw `type:"COGIS_READY"`, and dropped it as `unknown_type`.

The pre-existing STEP 2 guard (`event.source !== window`) did NOT catch this,
because on a same-window self-post `event.source === window` (the same
window is both sender and receiver of that dispatch).

**Fix:** added a STEP 0 that silently ignores three bridge-originated types
(`COGIS_READY`, `WEB_BRIDGE_RESULT_CHUNK`, `WEB_BRIDGE_PLATFORM_DONE`) at the
top of the handler, before origin check.

**M8a implication (real finding, not just harness cleanup):** the real M8a
bridge must filter its own outbound types explicitly, OR use a direction
tag on the envelope, OR post over a dedicated `MessageChannel`. This is a
design constraint for M8a — recorded in the file comments verbatim.

#### Bug 2 (fixed in PR #28) — `chrome.storage.session` threw

Every drop/accept path also logged
`persist_error: Cannot read properties of undefined (reading 'session')`.

Cause: `chrome.storage.session` from a content script requires (a) the
`"storage"` permission in the manifest AND (b) the SW to call
`chrome.storage.session.setAccessLevel("TRUSTED_AND_UNTRUSTED_CONTEXTS")`
before the content script can access it. Neither was set up in the harness.

**Fix:** dropped persistence entirely. Counters are module-scope in-memory
only, reset on page navigation. This matches the addendum's page-lifetime
handshake-session semantics. The spike page reads counters by parsing the
`[s8.1-bridge]` console log — which is the channel the finding writer uses
anyway.

**M8a implication:** if M8a wants counters that survive across tabs or
across a full SW lifecycle, it must either (a) request the `"storage"`
permission and grant `TRUSTED_AND_UNTRUSTED_CONTEXTS` from the SW, or
(b) pipe counter increments to the SW via `chrome.runtime.sendMessage` and
persist there. For M6 debug-panel purposes, (b) is the cleaner path — it
keeps the storage permission out of the manifest.

#### Bonus CSP findings (fixed in PR #28)

Chrome's console flagged two directives in the spike page's meta CSP:

1. **`connect-src 'none' alongside other keywords`** — combining `'none'`
   with other source expressions is invalid per spec. Also redundant given
   `default-src 'none'`. Removed.
2. **`frame-ancestors is ignored when delivered via <meta>`** — this
   directive only takes effect via an HTTP response header. GitHub Pages
   does not let us set headers.

**M8a implication for `web/index.html`:** the M8b page can only enforce a
subset of CSP via meta. `frame-ancestors` is unavailable via meta;
protection against clickjacking has to be either accepted as out of scope
(and the page written so it doesn't matter) or moved to a hosting platform
that lets us set headers. Recorded as a docs-only constraint for M8b.

### Round 2 — clean cold load, clean handshake

**Actions:**

1. PR #28 merged.
2. Reloaded extension at `chrome://extensions/` (reload icon on the card).
3. Hard-reloaded the spike tab (`Ctrl+Shift+R`).
4. Verified clean cold-load console.
5. Clicked "Send HELLO now (manual)".

**Observed:**

```text
[s8.1-page]   page_loaded    origin:"https://cogis.ai", readyState:"loading", sessionNonce:"dd03e3c92dadf18eae4ef8543344d0fd"
[s8.1-bridge] bridge_loaded  readyState:"interactive", runAt:"document_idle"
              counters:{all zeros}
[s8.1-page]   page_send_hello  label:"manual", nonce:"dd03e3c9..."
[s8.1-page]   page_recv        origin:"https://cogis.ai", sourceIsWindow:true, data:{type:"COGIS_HELLO", nonce:"dd03e3c9...", v:1}
[s8.1-bridge] accepted_hello   nonce:"dd03e3c9...", counters:{helloCount:1, acceptedCount:1, all-drops:0}
[s8.1-page]   page_recv        origin:"https://cogis.ai", sourceIsWindow:true, data:{type:"COGIS_READY", nonce:"dd03e3c9...", v:1, extVersion:"0.0.1", capabilities:{search:true, cancel:true}}
```

**Findings:**

- Handshake round-trip works end-to-end. Zero drops.
- Nonce is echoed byte-identical in `COGIS_READY`.
- The nonce differs from Round 1 (`0e3ea98e...` → `dd03e3c9...`), confirming
  fresh generation on each page load via `crypto.getRandomValues` — not a
  cached or deterministic value.
- SW console shows only `sw_loaded`; the handshake protocol is entirely
  page ↔ content-script. **The SW is only involved for `WEB_BRIDGE_SEARCH` /
  `WEB_BRIDGE_CANCEL` envelopes.** This is a useful architectural
  observation: SW wake-up is not on the handshake critical path.
- The favicon 404 (`GET https://cogis.ai/favicon.ico 404`) is cosmetic. Add
  a null-favicon meta or a real favicon in an M8b cleanup pass. Not a
  spike blocker.

### Round 3 — origin-lock drop matrix (§2 buttons)

**Actions:**

Clicked, in order:

1. `Attempt postMessage with target "*"`
2. `postMessage with target "https://cogis.ai.evil.example"`
3. `postMessage with target "http://cogis.ai"`

**Observed — Click 1 (`target: "*"`):**

```text
[s8.1-page]   page_attempt_target_origin  origin:"*"
[s8.1-page]   page_attempt_result         origin:"*", threw:false
[s8.1-page]   page_recv                   origin:"https://cogis.ai", sourceIsWindow:true, data:{type:"COGIS_HELLO", nonce:"dd03e3c9...", v:1}
[s8.1-bridge] accepted_hello              nonce:"dd03e3c9...", counters:{helloCount:2, acceptedCount:2, all-drops:0}
[s8.1-page]   page_recv                   origin:"https://cogis.ai", sourceIsWindow:true, data:{type:"COGIS_READY", ...}
```

Message WAS delivered. Bridge accepted it as a normal `COGIS_HELLO`. No
drops. `helloCount` and `acceptedCount` both incremented from 1 to 2.

**Observed — Click 2 (`target: "https://cogis.ai.evil.example"`):**

```text
[s8.1-page]   page_attempt_target_origin  origin:"https://cogis.ai.evil.example"
[s8.1-page]   page_attempt_result         origin:"https://cogis.ai.evil.example", threw:false
```

Then Chrome logged a **console warning** (not a thrown exception):

```text
Failed to execute 'postMessage' on 'DOMWindow': The target origin provided
('https://cogis.ai.evil.example') does not match the recipient window's
origin ('https://cogis.ai').
```

**No `[s8.1-bridge]` line.** Bridge never observed the message. Zero
counters moved.

**Observed — Click 3 (`target: "http://cogis.ai"`):**

Same shape as Click 2. Chrome warning:

```text
Failed to execute 'postMessage' on 'DOMWindow': The target origin provided
('http://cogis.ai') does not match the recipient window's origin
('https://cogis.ai').
```

No bridge observation. Zero counters moved.

**Findings from Round 3:**

- **`target: "*"` does NOT bypass origin lock.** `postMessage`'s target-origin
  is a *sender-side* control ("I'm willing to send to any origin"). The
  receiver still sees the true `event.origin` set by the browser. Since our
  sender IS `https://cogis.ai`, the message is delivered with the correct
  origin, so the bridge accepts it.

  **But** `*` is still a data-leakage risk: if the M8a page-side sender ever
  posts sensitive content with `target: "*"`, a hostile iframe on the page
  could read it via a `message` listener. **M8a page-side sender must always
  use exact-origin target: `"https://cogis.ai"`.** Recorded as a design
  constraint for M8a §3.9.

- **Wrong-host target-origin is rejected by the browser before the bridge
  sees anything.** The observable signal is a Chrome console warning; no
  counter increments. Chrome's protection here runs BEFORE our bridge's
  origin lock — the bridge is defense-in-depth.

- **Scheme mismatch counts as a mismatch.** `http:` vs `https:` fails
  origin match even when host and port are identical.

- **`originDropCount` is only useful for cases the browser lets through.**
  For explicit wrong-target-origin senders, Chrome blocks delivery — no
  bridge observation, no counter increment. **The M6 debug panel must
  surface both signals: the bridge counter AND any Chrome console warnings
  from the tab.** Recorded as an M6 design constraint.

- The `page_attempt_result.threw` field was `false` in all three cases —
  `postMessage` does not throw on wrong target-origin; it logs a warning and
  drops silently. Callers cannot observe the failure programmatically from
  the sender side.

### Round 4 — envelope-validation drops (§3 buttons)

**Setup note (matters):** at the start of Round 4 the page had been reloaded
(new session nonce `926b9bf6b5e27327e59c4ccd656b0c03`) and NO handshake had
been performed. `helloCount` was 0 throughout Round 4. This turned out to be
more informative than the originally-planned post-handshake sequence — see
"Bonus finding" at the end of this round.

**Actions:** clicked in order:

1. Send message with no `type`
2. Send message with unknown `type`
3. Send SEARCH with wrong nonce
4. Send SEARCH with non-string query
5. Send SEARCH with no requestId

**Observed — Click 1 (no `type`):**

```text
[s8.1-page]   page_send_malformed  kind:"no-type", msg:{nonce:"926b9bf6...", v:0.03}
[s8.1-page]   page_recv            origin:"https://cogis.ai", data:{nonce:"926b9bf6...", v:0.03}
[s8.1-bridge] drop_malformed       reason:"missing_type"
              counters:{malformedDropCount:1, others:0, helloCount:0}
```

As predicted: envelope with no `type` field is rejected at the first
validation check.

**Observed — Click 2 (unknown `type`):**

```text
[s8.1-page]   page_send_malformed  kind:"unknown-type", msg:{type:"HAX", nonce:"926b9bf6..."}
[s8.1-page]   page_recv            data:{type:"HAX", nonce:"926b9bf6..."}
[s8.1-bridge] drop_malformed       reason:"unknown_type", type:"HAX"
              counters:{malformedDropCount:2, others:0}
```

As predicted: `type` not in `ALLOWED_TYPES` set is rejected. Type value is
captured in the drop observation for diagnostics.

**Observed — Click 3 (SEARCH with wrong nonce):**

```text
[s8.1-page]   page_send_malformed  kind:"nonce-mismatch", msg:{type:"WEB_BRIDGE_SEARCH", nonce:"wrong-nonce", requestId:"r1", query:"x"}
[s8.1-page]   page_recv            data:{type:"WEB_BRIDGE_SEARCH", nonce:"wrong-nonce", requestId:"r1", query:"x"}
[s8.1-bridge] drop_nonce           received:"wrong-nonce", expected:null
              counters:{nonceDropCount:1, malformedDropCount:2}
```

**Note `expected:null`** — no handshake had completed, so `sessionNonce` was
still `null`. Nonce comparison `msg.nonce !== sessionNonce` was `"wrong-nonce" !== null` = true, so the message was dropped as a nonce mismatch. See
"Bonus finding" below — this is actually the desired behavior.

**Observed — Click 4 (SEARCH with non-string query):**

```text
[s8.1-page]   page_send_malformed  kind:"non-string-query", msg:{type:"WEB_BRIDGE_SEARCH", nonce:"926b9bf6...", requestId:"r2", query:12345, platforms:[]}
[s8.1-page]   page_recv            data:{type:"WEB_BRIDGE_SEARCH", nonce:"926b9bf6...", requestId:"r2", query:12345, platforms:[]}
[s8.1-bridge] drop_nonce           received:"926b9bf6...", expected:null
              counters:{nonceDropCount:2, malformedDropCount:2}
```

**Unexpected but correct:** this hit `drop_nonce`, not `drop_malformed` with
`reason:"bad_query"`. Why? Because `validateEnvelope` checks nonce match
BEFORE per-type field validity. With no handshake completed,
`sessionNonce === null`, so even the page's real session nonce fails the
mismatch check (`"926b9bf6..." !== null`).

**Consequence:** to observe `bad_query` distinctly, the handshake must
complete first. Deferred to Round 5.

**Observed — Click 5 (SEARCH with no requestId):**

```text
[s8.1-page]   page_send_malformed  kind:"no-requestId", msg:{type:"WEB_BRIDGE_SEARCH", nonce:"926b9bf6...", query:"x", platforms:[]}
[s8.1-page]   page_recv            data:{type:"WEB_BRIDGE_SEARCH", nonce:"926b9bf6...", query:"x", platforms:[]}
[s8.1-bridge] drop_nonce           received:"926b9bf6...", expected:null
              counters:{nonceDropCount:3, malformedDropCount:2}
```

Same story: nonce check short-circuits before `missing_requestId` can be
observed. Same deferral to Round 5.

**Final counter state after Round 4:**

```text
originDropCount:0, nonceDropCount:3, malformedDropCount:2, acceptedCount:0, helloCount:0
```

**Findings from Round 4:**

- **`missing_type` and `unknown_type` are pure envelope-shape checks and
  run BEFORE nonce validation.** They fire regardless of handshake state.
  A well-formed but wrong-type message is a `drop_malformed`, not a
  `drop_nonce`, because the type gate is upstream of the nonce gate.
- **All per-type field validation runs downstream of nonce validation.**
  `bad_query`, `missing_requestId`, `bad_platforms`, `bad_v` cannot be
  observed until the handshake has completed and `sessionNonce` is set.
  This is a validation-order finding, not a bug: the bridge fails closed on
  nonce before it examines the specific fields inside the envelope.
- **The drop-kind on `drop_nonce` includes both received and expected
  values.** `expected:null` when no handshake has run; `expected:"<nonce>"`
  after handshake. This is enough for the M6 debug panel to explain a
  nonce-drop to a developer: "handshake never happened" vs. "nonce didn't
  match."

**Bonus finding — pre-handshake protection is stronger than expected:**

Clicks 3, 4, and 5 all sent well-formed `WEB_BRIDGE_SEARCH` envelopes (right
type, matching nonce or plausible nonce, most fields correct) before the
handshake completed. All three were rejected at the nonce check because
`sessionNonce === null` at that point.

**This means the bridge is fail-closed against ALL work envelopes until the
handshake completes**, not just against explicitly-malformed ones. There is
no "skip the handshake and send a search anyway" attack surface. The
`sessionNonce === null` state acts as a global gate on every work-carrying
envelope.

The original stub's "SEARCH BEFORE handshake" question is therefore already
answered by Round 4 without needing a dedicated click: any envelope that
requires nonce validation (i.e. anything other than `COGIS_HELLO`) is
automatically dropped as `drop_nonce` when no handshake has occurred.
**Row deleted from Round 5's planned agenda.**

### Round 5 (planned) — post-handshake field validation + happy-path SEARCH+CANCEL

Refined based on Round 4's findings. "SEARCH BEFORE handshake" is now
considered already-answered; Round 5 focuses on the observations that
require an active handshake:

1. Complete handshake (click "Send HELLO now (manual)").
2. Click envelope-validation drops that were nonce-shadowed in Round 4:
   - "Send SEARCH with non-string query" — expect
     `drop_malformed reason:"bad_query"`.
   - "Send SEARCH with no requestId" — expect
     `drop_malformed reason:"missing_requestId"`.
3. Happy-path SEARCH: verifies the SW receives an accepted envelope via
   `chrome.runtime.sendMessage`, returns canned chunks, the bridge forwards
   them back to the page, and the page observes `WEB_BRIDGE_RESULT_CHUNK` +
   `WEB_BRIDGE_PLATFORM_DONE`.
4. Happy-path CANCEL: verifies `WEB_BRIDGE_CANCEL` is accepted and reaches
   the SW.

All four can be done in one continuous session without a page reload.

## M8a design constraints extracted from this spike

_(Feeds directly into `docs/spikes/s8-1-postmessage-handshake-contract.md`
and the M8a addendum. Not intended to be exhaustive; grows as observations
complete.)_

1. **Bridge must ignore its own outbound message types on inbound.** Filter
   by explicit outbound-type set (`COGIS_READY`, `WEB_BRIDGE_RESULT_CHUNK`,
   `WEB_BRIDGE_PLATFORM_DONE`) OR use a direction tag on the envelope OR
   use a dedicated `MessageChannel` per session.

2. **M8a page-side sender must always use `target: "https://cogis.ai"`.**
   Never `*`. Explicit target-origin is a data-confidentiality control, not
   just an integrity control.

3. **Counters must survive SW cycling and cross-tab observation.** Content
   scripts cannot use `chrome.storage.session` without extra manifest
   plumbing. Prefer SW-owned counters piped via `chrome.runtime.sendMessage`.

4. **M6 debug panel must surface both bridge counters AND Chrome console
   warnings** for the tab. `originDropCount` alone misses the most common
   failure class (browser-blocked wrong-target-origin sends).

5. **CSP via meta tag is a subset of CSP via response header.**
   `frame-ancestors` and some other directives are ignored via meta. If the
   M8b page needs clickjacking protection, it must be enforced at hosting.
   GitHub Pages doesn't let us set headers; this is a documented gap.

6. **Handshake is off the SW critical path.** SW wake latency does not
   affect handshake time. Wake latency only matters for SEARCH/CANCEL.

7. **Fail-closed against work envelopes until handshake completes.** The
   `sessionNonce === null` state acts as a global gate on every envelope
   that requires nonce validation. Attackers cannot skip the handshake and
   send a `WEB_BRIDGE_SEARCH` directly. **This is a load-bearing property
   of M8a's real bridge** — M8a code review must confirm the equivalent
   fail-closed behavior is preserved, ideally with a unit test that sends
   a `WEB_BRIDGE_SEARCH` before any `COGIS_HELLO` and asserts drop.

8. **Validation ordering matters for observability.** Per-type field errors
   (bad_query, missing_requestId, etc.) are downstream of the nonce check.
   Without a completed handshake, they cannot fire. M8a's real bridge
   should preserve this ordering so that the M6 debug panel's counter
   histogram reflects the true failure mode (e.g., "nonce mismatch" always
   dominates when the page hasn't handshaken yet, which is diagnostic
   information in itself).

  meta or a real favicon in an M8b cleanup pass.
- **Timing observation for `document_idle` vs page's inline emissions.**
  The spike page has three timing buttons ("Send HELLO immediately",
  "Send HELLO on DOMContentLoaded", "Send HELLO on window.load") that were
  designed for observation but wired to click-triggered emission instead
  of auto-emission at those lifecycle events. This is a harness gap. For
  the spike closing question ("does `document_idle` reliably run before
  page-emitted `COGIS_HELLO`?"), the observed cold-load ordering
  (`page_loaded` at `readyState:"loading"`, then `bridge_loaded` at
  `readyState:"interactive"`) tells us `document_idle` fired between
  those two states. Sufficient for the finding; a full lifecycle-timing
  matrix is deferred to M8a's real integration testing.
- **`SEARCH BEFORE handshake` button** turned out to be redundant with
  Round 4 clicks 3–5, which already sent well-formed SEARCH envelopes
  before handshake and confirmed the fail-closed behavior via `drop_nonce`.
  Not clicked; not needed.
- **`bad_query`, `missing_requestId`, `bad_platforms` visibility** requires
  a completed handshake because nonce validation short-circuits them.
  Round 5 will cover the two we care about (`bad_query`, `missing_requestId`).
  `bad_platforms` is deferred to M8a integration tests since Round 4
  already established validation-ordering.
- **Handshake session isolation across page reloads.** Every reload
  generates a fresh session nonce (`0e3ea98e...`, `dd03e3c9...`,
  `926b9bf6...` observed so far). A previous session's nonce becomes
  invalid the instant the page navigates. This matches the addendum's
  session-lifetime scope. No cross-page nonce reuse observed.
